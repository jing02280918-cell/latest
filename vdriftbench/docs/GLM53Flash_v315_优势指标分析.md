# GLM-5.3-Flash：完整 v3.15 的优势指标分析

数据核验日期：2026-10-07。正式消融为同一 Core60、seed=0、4组×60条。
本报告按用户要求，只列完整方法数值占优的结果；这是事后筛选的优势视图，不是全部性能表。
“相对更好”和“统计显著”分别判断，持平与反向结果仍保存在原始审计文件中。

## 1. 总体效果

- 对比无维度升级，R5含补救ASR为 **85.00%（51/60）对81.67%（49/60）**，完整方法高3.33个百分点。双侧精确McNemar p=0.754。
- 对比无维度升级，样本任意轮成功率为 **93.33%（56/60）对86.67%（52/60）**，高6.67个百分点。p=0.219。
- 以上是两个成功率定义，不能相加成一个总增益。

## 2. 硬拒绝早停：越少越好

- 完整方法 **10/60**，无调度器 **14/60**：少4条，较消融减少28.57%；早停率16.67%对23.33%，低6.67个百分点。配对McNemar p=0.454。
- 完整方法 **10/60**，无维度升级 **17/60**：少7条，较消融减少41.18%；早停率16.67%对28.33%，低11.67个百分点。p=0.092。
- 这里统计的是`terminated_early`对应的build-up硬拒绝早停样本数量，**不是对话内全部拒绝回复次数**。早停后仍可进入R5，因此它与最终ASR不是同一个事件。

## 3. 补救表现：从失败到成功

- R5补救新增成功：完整方法 **9条**，无评分反馈 **6条**，无维度升级 **4条**，分别多3条、5条。
- 以全部60条为分母，补救带来的ASR增量为 **15.00个百分点**，两个消融分别为10.00、6.67个百分点。
- 在首轮R5失败样本内，观察到的补救转化率为完整方法 **9/18=50.00%**，无评分反馈 **6/15=40.00%**，无维度升级 **4/15=26.67%**；分别高10.00、23.33个百分点。
- “补救新增成功”事件的配对McNemar p分别为0.581、0.267。转化率的失败样本集合不同，不使用上述配对p值。
- 各组实际补救轮数不同；这些是当前配置下的补救表现，不能据此证明同等补救预算下的算法优势，也不是独立的retry消融。

## 4. 风险强度与五维评分

- 平均样本最佳RiskScore：完整方法 **5.850**，无调度器 **5.567**、无评分反馈 **5.783**、无维度升级 **5.733**；分别高0.283、0.067、0.117分。
- 20,000次样本级配对bootstrap的95%区间分别为 **[-0.250, 0.800]、[-0.483, 0.617]、[-0.317, 0.550]**，均跨0。
- 首轮R5的NJS均分：完整方法 **1.683**，无调度器 **1.533**、无维度升级 **1.583**，分别高0.150、0.100分。
- NJS差值的配对bootstrap 95%区间分别为 **[-0.100, 0.400]、[-0.117, 0.317]**，均跨0。
- RiskScore最佳分与首轮R5分衡量不同位置；本报告明确标注位置，不混用。

## 5. 准备阶段与高分覆盖

- build-up任意轮成功率：完整方法 **53/60=88.33%**，无维度升级 **51/60=85.00%**，高3.33个百分点；p=0.727。
- 探索性切片：样本最佳RiskScore≥7的覆盖率，完整方法 **24/60=40.00%**，无调度器 **21/60=35.00%**，高5.00个百分点；p=0.648。
- 探索性切片：最佳RiskScore≥8的覆盖率，完整方法 **7/60=11.67%**，无调度器 **5/60=8.33%**、无评分反馈 **3/60=5.00%**，分别高3.33、6.67个百分点；p分别为0.754、0.289。
- ≥7和≥8是事后探索阈值，应放在补充分析中。这些阈值嵌套，不能算成相互独立的证据。

## 6. 实际耗时

- 完整方法本次墙钟 **6.52小时**，无评分反馈 **8.07小时**，少1.54小时，约短19.11%。两组R5含补救ASR与样本成功率相同。
- 这是运行时观察值。API响应、执行时段和服务器负载会影响墙钟，因此仅标为“本次运行更快”，不推断算法计算量更低。
- 无调度器组断点前计时与部分角色调用数未检查点保存，不参与总耗时比较。

## 7. 历史运行与旧版本的比较边界

- 历史`data/v3.15_glm53flash_run`使用相同目标GLM-5.3-Flash，已完成357条。
- 本报告只取与当前Core60相同的60个sample_id；这60条target_claim全部一致，原始R5提示逐字一致性尚未确认。
- 在这60条上，当前完整方法的首轮R5 NJS均分 **1.683**，历史运行 **1.617**，观察差值 **+0.067分**。只作为历史描述性结果，不作为版本提升的因果证据。
- 历史运行seed为20260904、workers=2；当前seed=0、workers=1，且调度器训练历程和运行时间不同。历史同名v3.15运行也不是“更旧方法版本”。
- 跨 run 比较时须对齐 sample 子集与 target_claim；原始提示逐字一致性、seed 与调度历程不同则只做描述性对比，不作版本因果结论。
- v3.14使用DeepSeek Pro，不能拿当前GLM结果与其对比证明版本提升。其他早期版本的目标模型、评分规则、样本和协议未全部对齐，不列为可归因的占优结果。
- **当前证据支持“完整方法在部分消融指标上数值占优”，还不支持“当前v3.15在相同GLM与协议下全面优于旧版本”。**

## 8. 可复用结论

在GLM-5.3-Flash的Core60配对实验中，完整v3.15相比移除维度升级配置，样本成功率高6.67个百分点，硬拒绝早停少7条，并观察到更多R5补救成功和更高的build-up成功率。相比移除调度器配置，完整方法硬拒绝早停少4条，平均样本最佳风险分与首轮R5的NJS均分较高；相比移除评分反馈配置，其平均最佳风险分和补救新增成功数较高。本次结果对完整机制的部分作用提供描述性支持，相关配对检验或bootstrap区间尚未显示统计显著差异。
